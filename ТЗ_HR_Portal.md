## 1. Общее описание

HR-портал Halyk Bank — веб-приложение для самообслуживания сотрудников в части кадровых процессов. Позволяет подавать заявки, отслеживать их статусы, проходить онбординг и смотреть HR-аналитику.

### 5.2 Каталог сервисов (`catalog`)

**Навигация внутри каталога — двухуровневая (drill-down):**

**Уровень 1: Плитки групп**
- Поиск (текстовое поле, фильтрует по названию сервиса и категории)
- Фильтры-Pills по категориям: «Все» + все уникальные `cat` из SERVICES
- Сетка плиток: 3 колонки (десктоп) / 2 колонки (мобайл)
- Каждая плитка: иконка группы + название группы + количество сервисов + стрелка «›»
- Hover: зелёная тень + зелёная рамка
- Клик → переход на Уровень 2

**Уровень 2: Сервисы внутри группы**
- Кнопка «← Все группы» → возврат на Уровень 1
- Заголовок: иконка + название группы
- Сетка карточек сервисов: 3 колонки (десктоп) / 1 колонка (мобайл)

**Особые случаи:**
- При вводе текста в поиск → автоматически сброс выбранной группы, показываются все совпадающие сервисы из всех категорий плоским списком
- Смена фильтра-Pill → сброс выбранной группы
- Сервисы без группы (`group` отсутствует) выводятся отдельным блоком «Другие сервисы» на уровне 1

**Карточка сервиса:**
- Иконка в зелёном квадрате (44×44px, borderRadius 12)
- Метка категории/группы (uppercase, зелёный)
- Название (жирное, 14px)
- Описание (12px, серый)
- SLA («⏱ N раб. дней»)
- Кнопка «Подать заявку» → переход на форму  
  *Исключение: сервис с `isOnboarding: true` → кнопка «Открыть» → переход на страницу Онбординга*

### 5.4 Форма подачи заявки (`form`)

Открывается поверх каталога (меняется `page` → `"form"`).

#### 5.4.1 Стандартная форма (обычный сервис)

Отображается для всех сервисов, кроме `isApproval: true`.

**Верхний блок — информация о сервисе:**
- Иконка + название + SLA
- Описание
- «Кто подаёт» и «Необходимые документы» (если указаны)

**Поля формы:**
- ФИО сотрудника (Input)
- Подразделение (Input)
- Комментарий к заявке (Input, multiline)

**Кнопки:**
- «Подать заявку» → создаёт запись в `requests`, показывает экран подтверждения
- «← Назад в каталог»

**Экран подтверждения:**
- Зелёная галочка ✓
- «Заявка отправлена!»
- Номер заявки (HR-00N)
- Кнопка «В мои заявки»

#### 5.4.2 Форма согласования кандидата (`isApproval: true`)

Многошаговая форма с вкладками.

**Вкладка 1: Личные данные**
- Фамилия, Имя, Отчество
- Дата рождения
- ИИН
- Серия / номер удостоверения
- Дата выдачи, дата истечения

**Вкладка 2: Вакансия и оффер**
- Должность
- Подразделение
- Уровень зарплаты (₸)
- Направление бизнеса (select: Зампред ГБ / МСБ / РБ / Безопасность / Председатель)
- Организация (ГБ / ДО)

**Вкладка 3: Образование** (из резюме)
- Динамический список: Учебное заведение + Степень + Год
- Кнопка «+ Добавить»

**Вкладка 4: Опыт работы** (из резюме)
- Динамический список: Компания + Должность + Период + Обязанности
- Кнопка «+ Добавить»

**Вкладка 5: Родственники**
- Динамический список: Фамилия / Имя / Отчество / Степень родства / Адрес / Место работы / ИИН / Телефон
- Кнопка «+ Добавить»

При отправке → запись с `isApproval: true` добавляется в `requests`.

#### 5.5.1 Список заявок

Каждая строка:
- Иконка сервиса

- Badge со статусом

**Статусы заявки:**

| Ключ | Метка | Цвет |
|---|---|---|

| `sent` | Отправлена | blue |
| `review` | Проверка | orange |

Клик на строку → открывает детейл (правая панель или отдельный экран).

#### 5.5.2 Детейл обычной заявки

- Кнопка «← Назад»
- Иконка + название + ID
- WorkflowBar (прогресс-бар по всем 7 статусам)
- Таймлайн событий (mock)

**WorkflowBar:** горизонтальная шкала из 7 кружков (пронумерованы 1–7), соединённых линиями. Выполненные шаги — зелёный кружок с галочкой, текущий — зелёный с оранжевой рамкой, будущие — серые.

#### 5.5.3 Детейл заявки на согласование кандидата (`isApproval: true`)

- Данные кандидата: ФИО, должность, подразделение, зарплата
- **ApprovalBar** — маршрут согласования из 7 этапов

**Этапы ApprovalBar:**

| ID | Роль | Организация |
|---|---|---|
| recruiter | Рекрутер | ДО |
| do | Согласование ДО | ДО |
| business | Рук. направления ГБ | ГБ |
| usot | Спец. УСОТ ГБ | ГБ |
| hr_dir | HRD ГБ | ГБ |
| do_date | ДО: дата выхода | ДО |
| uap | УАП ГБ | ГБ |

Визуальное состояние каждого этапа: одобрено (зелёный), отклонено (красный), активно (оранжевый с пульсацией), ожидает (серый пунктир).

Активным считается первый этап без решения, при условии что все предыдущие одобрены.

Плашка ГБ/ДО над каждым кружком: синяя (ГБ) / зелёная (ДО).

- Вкладки с данными: Личные данные / Образование / Опыт работы / Родственники

**Кнопки действий (для ролей-согласантов):**
- «Одобрить» → устанавливает `decisions[activeStage] = "approved"`
- «Отклонить» → устанавливает `decisions[activeStage] = "rejected"`

### 5.6 Онбординг (`onboarding`)

Страница адаптации нового сотрудника. Поддерживает несколько ролей и режимов просмотра.

#### 5.6.1 Переключатель ролей (Role tabs)

| Роль | Описание |
|---|---|
| `employee` | Новый сотрудник |
| `manager` | Руководитель |
| `mentor` | Наставник |
| `it` | IT-онбординг (только для IT-специалистов) |
| `hr` | HR-менеджер (обзорный режим) |

#### 5.6.2 Фазы онбординга (OB_PHASES)

| ID | Метка | Период |
|---|---|---|
| `pre` | Pre-boarding | До выхода |
| `week1` | День 1–7 | Неделя 1 |
| `month1` | Месяц 1 | День 8–30 |
| `month3` | Мес. 2–3 | День 31–90 |

#### 5.6.3 Режим «Сотрудник» (employee)

**Шапка:**
- Прогресс-кольцо (% выполненных задач)
- Уровень геймификации (6 уровней: Новичок → Исследователь → Освоился → Уверенный игрок → Профессионал → Легенда Halyk)
- Монетки «Спасибо» (очки, текущее значение: 12)
- Стрик дней (текущее: 3 дня)
- Бейджи (4 типа: Первый шаг / Половина пути / Команда приняла / Адаптирован)

**Фазовые вкладки:** Pre-boarding / День 1–7 / Месяц 1 / Мес. 2–3

**Список задач по выбранной фазе:**
- Чекбокс + название + «Кто выполняет»
- Выполненные задачи — зачёркнуты, фон зелёный
- Особые задачи:
  - `isManagerMeeting: true` → кнопка «Запросить встречу» (mock)
  - `isSurvey: true` → кнопка «Пройти опрос» → открывает форму опроса
  - `info` → иконка ℹ️ с подсказкой
  - `instruction` → серый текст под названием

**Опрос сотрудника (SURVEY_EMPLOYEE):**
14 вопросов. Типы вопросов: single-choice (radio), text (textarea). После ответа на все вопросы — кнопка «Отправить».

**Раскрываемые секции (accordion):**

| Секция | Содержимое |
|---|---|
| Документы | Список документов с статусом: verified / pending / waiting |
| Адрес и контакты | Форма с адресом и телефоном (mock) |
| Льготы | 8 льгот: ИПО / СВЗ / ВЛ / ОТП / ДЕТ / СКД / IT / ПФ |
| Цели на ИС | Список целей с чекбоксами + добавление новой цели |
| Корпоративные сообщества | Вступить в Telegram-каналы (mock) |
| Спорт в Halyk | (mock) |
| Ценности банка | Квиз из 6 сценариев (выбор корпоративной ценности) |
| Здоровье | (mock) |
| Коммуникации | (mock) |
| Принципы работы | (mock) |

**Milestones-награды:**
При полном выполнении задач фазы появляется toast-уведомление с наградой:
- Pre-boarding + ONB → Ручка и блокнот
- Induction → Кружка Halyk
- Feedback → Футболка Halyk

**Spasibo-монетки:**
Накапливаются за задачи. Пороговые награды: 50→Кружка / 100→Футболка / 150→Термокружка / 200→Рюкзак / 300→Premium-мерч.

## 6. Модель данных

### 6.1 Сервис (SERVICES item)

```
{
  id: number,             // уникальный идентификатор
  cat: string,            // категория (для фильтра-Pill)
  group?: string,         // группа внутри категории (для drill-down)
  icon: string,           // emoji-иконка
  title: string,          // название сервиса
  sla: string,            // срок исполнения (текст)
  desc: string,           // описание
  who: string,            // кто подаёт заявку
  docs: string,           // необходимые документы
  tag?: string,           // дополнительная метка (рук / секретари)
  isApproval?: boolean,   // особая форма согласования кандидата
  isOnboarding?: boolean, // ведёт на страницу онбординга
}
```

### 6.2 Заявка (requests item)

```
{
  id: string,           // HR-00N
  title: string,        // название
  status: string,       // draft|sent|review|assigned|inwork|done|closed
  sla: string,
  date: string,         // дата в формате DD.MM.YYYY
  icon: string,
  // Только для isApproval:
  isApproval?: boolean,
  candidate?: string,
  position?: string,
  dept?: string,
  salary?: string,
  businessDir?: string,
  org?: string,
  decisions?: {
    recruiter: "approved"|"rejected"|null,
    do: ..., business: ..., usot: ..., hr_dir: ..., do_date: ..., uap: ...
  },
  personal?: { lastName, firstName, patronymic, dob, iin, passportNo, passportIssued, passportExpiry },
  education?: [{ institution, degree, year }],
  experience?: [{ company, role, period, duties }],
  relatives?: [{ lastName, firstName, patronymic, relation, address, workplace, iin, phone }],
}
```

## 8. Бизнес-логика

### 8.1 Фильтрация сервисов

```
filteredServices = SERVICES.filter(s =>
  (catFilter === "Все" || s.cat === catFilter) &&
  (s.title.includes(search) || s.cat.includes(search))
)
```

### 8.2 Добавление заявки

При отправке стандартной формы:
- Создаётся объект `{ id: HR-00N, title, status: "sent", sla, date, icon }`
- Добавляется в начало массива `requests`
- Показывается экран подтверждения

### 8.3 ApprovalBar — активный этап

Активен первый этап, у которого `decisions[id] === null` и все предшествующие `=== "approved"`.

### 8.4 Геймификация онбординга

- Прогресс = `выполненных задач / всего задач * 100%`
- Уровень определяется по порогам: 0% → Уровень 1 (Новичок) ... 91%+ → Уровень 6 (Легенда Halyk)
- Toast-уведомление при полном завершении фазы (`pre`, `ob`, `ind`, `feed` в активностях HR-вида)

### 8.5 Квиз ценностей

6 сценариев, последовательно. Пользователь выбирает корпоративную ценность из 3 вариантов. После каждого ответа показывается правильный. Итоговый счёт: N/6.

## 9. Деплой

| Параметр | Значение |
|---|---|
| Хостинг | GitHub Pages, репозиторий `dbakieva1985-commits/Hr` |
| Ветка исходников | `claude/hr-portal-prd-0pv4m1` |
| Ветка деплоя | `gh-pages` |
| Базовый путь | `/Hr/` |
| Команда сборки | `PUBLIC_URL=/Hr npm run build` |

**Процесс деплоя:**
1. Сборка из ветки `claude/hr-portal-prd-0pv4m1`: `PUBLIC_URL=/Hr npm run build`
2. Копировать `build/static/js/main.<hash>.js` в `gh-pages/static/js/`
3. Обновить ссылку в `gh-pages/index.html` (`sed -i 's|main\.[a-f0-9]*\.js|main.<новый_hash>.js|g' index.html`)
4. Добавить в коммит только: `index.html`, новый JS-файл, новый LICENSE-файл
5. `git push origin gh-pages`

**Важные ограничения при деплое:**
- Папка `tracker/` в ветке `gh-pages` — **не трогать** (отдельное приложение — трекер кандидатов)
- Папка `catalog/` в ветке `gh-pages` — **не трогать**
- Не делать `git add .` — добавлять только конкретные файлы
